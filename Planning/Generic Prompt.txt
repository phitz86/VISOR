Refactor Relative view models
 - We've been calculating time gaps for our Relative display block based on some smoothed estimations using CarIdxLapDistPct. Prototype Radar Display
 - It's time to take a stab at the "R" in VISOR. A radar display should be a separate window from MainWindow, but with the same translucent style and drag to reposition feature, and the same launch behavior (i.e. after ConfigWindow closes). After we've got it working the way we want, we will want the window to auto-hide when there are no cars close to us.
 - The size of the window should be 300x300 pixels, and it should be positioned in the upper right quadrant of the display, with similar center-offset logic as we used on the MainWindow.
 - The Radar window should be a simple target-style UI with two concentric rings and a crosshair, with the user's car in the center as a green rectangle, and other cars depicted as class-colored rectangles, positioned according to the logic we'll develop.
 - The concentric rings should be calculated to be 2 and 4 car lengths, respectively. To calculate these rings and the car positions within them, we should use CarIdxLapDistPct and the TrackLength variable from the session data. The outer boundary of the display (i.e. when we start or stop displaying cars) should be 5 car lengths.
 - The variables we need to use to position other cars in the display are CarLeftRight and CarIdxLapDistPct.
 - Other car blips should be colored according to their class, using the same scheme we developed for the Relative display. 
 - We also need to overlay the blips with the car's number, which we also already parsed for the Relative display. The sizes of the blips and car numbers should be selected so that the car number fits within the blip. The font should be white with a slight black outline so that it stands out, but it can be the default font.
